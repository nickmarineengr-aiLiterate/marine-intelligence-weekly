Maritime Regulatory Knowledge Repository

A document-centric repository — not a flat list — decomposing conventions/codes to paragraph level, with typed bidirectional cross-references, a citation engine, amendment/version/edition history, a cross-cutting definitions glossary, and Engineering Objects linking real-world equipment to every provision that governs it. Fully offline; runs from generated JSON only.

Every standard, grouped by package — browse the hierarchy without searching.

Cross Reference Explorer

Pick any regulation, code, circular, definition, or engineering object and drill down through its typed relationship graph — interprets, implements, amends, supersedes, cites, depends on, and related engineering objects.

Engineering Object Explorer

Real-world equipment and systems, browsable by concept rather than by document — every applicable convention, code, IRS rule, circular, definition, and cross-referenced object in one place.

Study Mode

An optional study interface layered on the existing repository data — prerequisite documents, a suggested reading order, recently amended regulations, the most frequently referenced provisions, related equipment, and the definitions glossary.

Editorial Dashboard

Internal maintainer tooling — what needs editorial attention, and the QA reports that back it up. Nothing here changes repository data; it only reads the last build's health check, change log, and workflow state.

Repository QA Reports

Coverage, Integrity, Citation, Relationship, Definition, Engineering Object, Package, and Repository Health — each exportable as JSON or a standalone HTML page.

Repository Diff Viewer

Compares a standard's decomposed tree between two points in its git history — new regulations, modified summaries, new relationships, and new definitions/engineering objects added in between. Computed by repository/build/diff-report.js (git-based; a static app can't do this itself) and rendered here from the generated report.

Expansion Manager

Packages completed/in-progress/planned, priority, source availability, verification status, and estimated effort — merging the hand-curated expansion plan with computed coverage facts so a stale plan can't silently drift from what the repository actually contains. See ROADMAP.md for the narrative version.

Amendment Tracker

Current version, latest amendment, pending amendments, last repository review, and next review required per standard — computed from CHANGELOG.json and the maintenance cadence policy (see MAINTENANCE_SCHEDULE.md).

Repository Metrics

A real growth trend reconstructed from git history (not a single-point estimate) — every commit that touched the repository's manifest, replayed via `git show`.

Repository Coverage Matrix

Document/chapter/regulation/paragraph-level presence, verification percentage, relationship completeness, and Engineering Object coverage — per standard and rolled up per package.
