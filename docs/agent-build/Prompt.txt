# Build Token-Efficient Production Agents for QB and MIW Notes

You are working inside the existing Marine Intelligence Weekly project and already understand its repository structure, production workflow, quality standards, and available production skills.

I want you to design and implement two separate Claude Code agents:

1. **QB Production Agent**
2. **MIW Notes Production Agent**

These agents are part of the **Marine Intelligence Weekly project only**. They are not part of RulesApp and must not introduce RulesApp architecture, schemas, governance, terminology, or dependencies into this work.

## Primary Objective

The purpose of these agents is to reduce repeated Claude token consumption by moving routine, deterministic, and repeatable production work into the Python programs and local tooling already built in the MIW project.

Claude must remain in the workflow, but primarily as:

* workflow engineer;
* task planner;
* exception handler;
* engineering judgement layer;
* regulatory verification layer;
* amendment and correction reviewer;
* final quality-control reviewer before Founder review.

Claude should not repeatedly regenerate entire documents when the same work can be performed deterministically by Python.

The intended operating model is:

```text
Source material
      ↓
Deterministic local extraction and preprocessing
      ↓
Python-based document construction
      ↓
Targeted AI intervention only where judgement is required
      ↓
Deterministic validation and quality checks
      ↓
Claude final engineering and editorial review
      ↓
Founder review
```

The local repository and generated files remain the authoritative working state. Chat history must not become the only place where production state, decisions, or corrections exist.

# Part B — Core Design Principle

The agents must use the lowest-cost reliable method for each operation.

Use the following execution hierarchy:

## Level 1 — Deterministic Python

Use Python without AI for work such as:

* file discovery;
* page and file sequencing;
* text extraction from machine-readable PDFs;
* OCR-result ingestion where OCR has already been performed;
* Markdown scaffolding;
* heading normalization;
* template population;
* question numbering;
* metadata generation;
* filename generation;
* source manifest creation;
* checksum generation;
* chapter assembly;
* duplicate detection;
* known-format conversion;
* callout formatting;
* table formatting;
* standard section insertion;
* validation against schemas;
* missing-section checks;
* broken-link checks;
* forbidden-placeholder checks;
* terminology checks;
* consistency checks;
* report generation;
* queue and status updates;
* packaging outputs for review.

## Level 2 — Small, Bounded AI Tasks

Use AI only for isolated tasks that genuinely require interpretation, such as:

* interpreting unclear handwritten text;
* resolving ambiguous engineering wording;
* identifying probable transcription errors;
* classifying content into an existing chapter structure;
* detecting whether two technically similar questions are materially different;
* drafting a missing explanation from verified source material;
* reconciling conflicting technical statements;
* proposing corrections that require engineering judgement;
* identifying likely regulatory references for subsequent verification.

Each AI call should receive only the minimum relevant source block, surrounding context, task instructions, and required output schema.

Do not send the entire corpus or entire chapter unless necessary.

## Level 3 — Claude Engineering Review

Claude should review:

* unresolved ambiguities;
* technical correctness;
* engineering logic;
* operational realism;
* regulatory accuracy;
* amendment status;
* internal contradictions;
* examination suitability;
* unsupported claims;
* whether deterministic tools altered technical meaning;
* whether the final document meets MIW publication standards.

## Level 4 — Founder Review

No output becomes final or published merely because an agent completed it.

The final state before publication must be:

```text
READY_FOR_FOUNDER_REVIEW
```

Only I can approve publication or canonical acceptance.

# Part C — QB Production Agent

Build a dedicated QB Production Agent for producing and maintaining MEO Class I question-bank material.

## Required Functions

The QB agent should be able to:

1. Accept the next source batch of questions from supported inputs.
2. Register every source file and preserve provenance.
3. Extract or ingest the question text.
4. Normalize formatting without silently changing meaning.
5. Separate questions accurately.
6. Detect:

   * exact duplicates;
   * formatting duplicates;
   * probable near-duplicates;
   * related but distinct questions;
   * examiner-specific variants;
   * multi-part questions;
   * incomplete questions;
   * questions requiring Founder judgement.
7. Compare new questions against the existing QB corpus.
8. Assign each question to the appropriate:

   * subject;
   * topic;
   * subtopic;
   * examiner;
   * source;
   * date or batch;
   * answer-production status.
9. Generate or update deterministic production records.
10. Prepare bounded packets for AI-assisted review only where needed.
11. Run all available validation checks.
12. Present Claude with only the questions requiring engineering or editorial judgement.
13. Generate a final review report.
14. Stop at `READY_FOR_FOUNDER_REVIEW`.

## Answer Production

Where answer production is included, reuse the established MIW or MEO Class I answer framework already present in the repository.

Do not invent a new answer template without first checking the canonical template.

The agent should distinguish between:

* raw question intake;
* question normalization;
* duplicate classification;
* answer drafting;
* answer verification;
* regulatory verification;
* final editorial review.

These stages must have separate statuses so that failed or incomplete work cannot appear finished.

## QB Quality Rules

The QB agent must not:

* merge technically distinct questions merely because wording is similar;
* delete source wording;
* silently correct a question without recording the correction;
* fabricate examiner names, dates, regulations, figures, or shipboard details;
* generate unsupported answers;
* treat AI confidence as proof;
* overwrite canonical records without a reviewable change record.

For every correction, preserve:

```text
original_text
normalized_text
correction_reason
correction_method
source_reference
review_status
```

# Part D — MIW Notes Production Agent

Build a separate MIW Notes Production Agent for converting source notes into publication-grade MIW Engineering Management Handbook chapters.

The immediate priority is the remaining **Uday handwritten notes PDF pages**.

These pages need to be:

1. transcribed;
2. structured;
3. technically interpreted;
4. verified;
5. corrected;
6. updated for current requirements;
7. amended where applicable;
8. expanded into the established MIW Notes format;
9. reviewed by Claude;
10. submitted for Founder review.

This MIW Notes work is a priority before I resume major RulesApp work.

## Important Workflow Change

The previous workflow was:

```text
Uday handwritten notes
      ↓
Google Gemini performs full transcription and chapter generation
      ↓
Gemini output manually copied into a text file
      ↓
Text file uploaded to Claude
      ↓
Claude verifies, validates, corrects, amends, and converts it into MIW format
```

This consumes unnecessary AI tokens, duplicates work, introduces manual copying, and makes provenance and correction tracking weak.

Replace it with a repository-based pipeline.

The preferred future workflow is:

```text
Uday source PDF pages
      ↓
Local source registration and page manifest
      ↓
Deterministic page extraction / image preparation
      ↓
Transcription stage
      ↓
Local transcription files stored page-by-page
      ↓
Deterministic normalization and chapter grouping
      ↓
Python builds chapter scaffold from MIW template
      ↓
Targeted AI tasks for interpretation and expansion
      ↓
Regulatory and technical verification
      ↓
Deterministic validation
      ↓
Claude final review
      ↓
Founder review
```

## Transcription Policy

Do not make full-document visual transcription by Claude the default method.

Evaluate the available source PDFs and determine:

* whether they contain a usable text layer;
* whether local OCR already exists;
* whether existing extraction tools can be reused;
* whether page images need to be generated;
* whether an external transcription model remains necessary;
* which pages require human or Claude intervention because handwriting is unclear.

Store transcription locally as a separate source layer.

The transcription must not be mixed immediately with corrected or expanded content.

Maintain at least these distinguishable layers:

```text
1. source_page
2. raw_transcription
3. normalized_transcription
4. corrected_source_notes
5. expanded_chapter_draft
6. verified_chapter
7. founder_review_version
```

Every correction must be traceable back to the original page.

## Required MIW Notes Agent Functions

The MIW Notes agent should:

1. Discover and register the next source files or page batch.
2. Generate a page-level manifest.
3. Record page number, file, checksum, source type, and processing status.
4. Ingest page-by-page transcription.
5. Flag uncertain words or unreadable passages explicitly.
6. Prevent guessed text from being treated as confirmed text.
7. Normalize transcription deterministically.
8. Identify likely chapter boundaries.
9. Propose how many chapters are required.
10. Produce a chapter plan before drafting.
11. Map source pages to planned chapters.
12. Build the chapter structure using the existing MIW Notes template.
13. Insert source-derived content into the relevant sections.
14. Identify gaps requiring authoritative research.
15. Use AI only for bounded technical expansion.
16. Verify regulatory references against authoritative sources.
17. Record amendment status and applicable dates.
18. Correct outdated or technically incorrect source notes without erasing the original.
19. Generate tables, examination questions, memory boxes, and operational examples using structured templates.
20. Run deterministic completeness and consistency checks.
21. Submit the assembled chapter to Claude for final technical and editorial review.
22. Produce a review report and Founder decision packet.
23. Stop at `READY_FOR_FOUNDER_REVIEW`.

* Send only relevant source excerpts to Claude.
* Use structured JSON or compact Markdown packets for AI tasks.
* Avoid resending unchanged chapter content.
* Use patch-based revision rather than full-document regeneration.
* Generate diffs between versions.
* Cache completed AI decisions where safe.
* Reuse verified regulatory references.
* Maintain a local terminology and standard-reference catalogue.
* Use deterministic validators before Claude review.
* Present Claude only with failed checks, uncertainty flags, diffs, and high-risk sections.
* Separate mechanical formatting from engineering review.
* Prevent repeated review of unchanged sections.
* Record why an AI call was required.

For each proposed AI step, explain why Python alone is insufficient.
