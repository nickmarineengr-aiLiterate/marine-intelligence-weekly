## 1. What the question demands

> a). Explain Fault Tree Analysis (FTA) with relevant examples. (8) b). Construct the Fault tree for “Engine Starting Failure” i.e., the engine speed goes down and finally stops. (8)

**Intent.** Limb (a) is bookwork: explain the technique, with examples. Limb (b) is application: construct an actual fault tree for a stated top event. The examiner is testing whether the candidate can move from describing a method to using it - and, less obviously, whether the candidate reads the printed top event carefully enough to notice that it describes two different failures.

**Mark allocation.** 16 printed as 8 + 8. Limb (a) is theory and should be written quickly and precisely - a symbol table and a numbered method. Limb (b) is a drawing, and eight marks for a drawing means the examiner is counting branches, gates and levels, which makes breadth more valuable than depth in any single branch.

**Examiner expectation.** Correct gate logic above all - OR for any, AND for all - a properly defined top event, at least three developed branches, and basic events drawn at a sensible resolution limit. The discriminating expectations are that the candidate notices the contradiction in the printed top event, includes human and organisational events, and includes spurious trips rather than only genuine faults.

The answer is decomposed into these required components:

- (a) What FTA is, and how it differs from the other analysis techniques
- (a) The symbols and the two gates that carry the logic
- (a) The method - how a tree is actually built
- (a) What the finished tree is used for, including minimal cut sets
- (b) Resolving the printed top event, which describes two different failures
- (b) The starting-air branch
- (b) The fuel and combustion branch
- (b) The trips, load and support-system branches that make a running engine slow and stop
- (b) Reading the finished tree - single-point failures and what redundancy does to them

## 3. The finding that mattered

**The printed top event contradicts itself, and that is the finding.**

The examiner names the top event **"Engine Starting Failure"** and then glosses it as *"the
engine speed goes down and finally stops"*. Those are **two different failures**: one is an
engine that will not start, the other is a running engine that stops.

Under the standing rule that examiner and source errors are **preserved and never silently
normalised**, the printed wording is reproduced exactly in `text_verbatim` and the anomaly is
recorded in `unresolved` rather than corrected into what the examiner probably meant. The answer
resolves it the way a candidate should: **state the ambiguity in one line and develop both** under
a single top event. That costs little, because the fuel, control and support branches are common
to both readings -- and it demonstrates the precise top-event definition that limb (a) names as
step one of the method.

The second finding is that the completed tree makes a point the question does not ask for but
which is worth the marks: **the tree is dominated by OR gates**, so the top event has many
order-1 minimal cut sets -- many single-point failures. That is the correct and sobering result
for a single-screw ship, and it is what connects the technique to **ISM element 10.3**: every
order-1 cut set is a candidate for the critical equipment list, and the stand-by arrangements it
identifies are exactly those the Code requires to be regularly tested.

**No failure rate, probability or MTBF is quoted.** Quantitative FTA needs plant-specific failure
data no candidate holds. The answer explains the qualitative evaluation -- which is what the
question asks for -- and states what quantification would require rather than inventing a number
to look rigorous. The tree is declared a **worked example**, not a complete analysis of any
particular engine, because trips and control architecture differ between makers and between
camshaft-controlled and electronically controlled engines.
